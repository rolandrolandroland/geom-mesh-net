# Implicit Neural Reconstruction of Atomic Clusters

## Outline and roadmap

This document specifies the reconstruction track. The track estimates the
solute field of a thinned, labelled 3D point pattern as a continuous function.
It checks that estimate against an exact oracle, then turns the field into
precipitates. It replaces the five-week design document of 2026-09-14, whose
problems are listed in Section 9. It also assesses three later proposals for
putting spatial statistics into the network (Section 7).

It runs alongside `experiments/inference/ROADMAP.md` rather than replacing it.
That track estimates four global parameters with calibrated uncertainty; this one estimates
*where* the solute is. They share the simulator, the data, the feature library
and the rule that every stage has a gate stated before it runs.

Every number below was measured on this repository's data on 2026-09-14 or
2026-09-15, using development patterns only, unless labelled an estimate. Each
one is regenerated by a script in `experiments/reconstruction/pilot/`, which writes
its results to `experiments/reconstruction/pilot/results/`.

## 1. The problem

An atom probe measurement is a list of atom positions and chemical identities,
and it records only a fraction of the atoms. A materials scientist wants more
than the four population parameters the inference track estimates. They want to
know where each precipitate is, how large it is and what it contains. They also
want a concentration field from which to draw isoconcentration surfaces and
proximity histograms.

Standard practice gets there with one of two heuristics:

- **Delocalisation.** Voxelise the atoms, smooth with a Gaussian kernel, and
  threshold the result into isosurfaces.
- **Cluster finding.** Run the maximum separation method or DBSCAN on the solute
  atoms.

Both have user-chosen parameters. Neither has a measured accuracy, because a
real measurement has no ground truth.

This package does have a ground truth. It owns the simulator, so for every
simulated pattern it can compute exactly the probability that each atom is a
solute atom (Section 4.2). That turns "how good is this reconstruction?" from a
judgement into a measurement. It also allows a fair test of whether an implicit
neural representation improves on delocalisation where delocalisation is
weakest. The representation can be fitted to one pattern or trained across
thousands of simulated ones. The weak spots are small precipitates, low detector
efficiency and precipitate edges.

## 2. Precise problem statement

### 2.1 The forward model

The 1,000 patterns in `data/` were produced by
`scripts/generate_data.py` calling `clustersim.clustersim`.

| Step | What happens | Code |
| --- | --- | --- |
| Atoms | 216,000 positions, independent and uniform in a 60³ box | `gen_rand_points` |
| Geometry | centres from a scaled, cropped, randomly subsampled cubic lattice; radii ~ N(`cr`, (`rb`·`cr`)²), negative values set to 0 | `clustersim` |
| Cluster labels | for each cluster, take the N_k atoms within r_k; round(`rho_c`·N_k) of them become guests by weighted sampling without replacement, weight 1 − d/d_max | `assign_clust_points` |
| Overlaps | an atom picked by any cluster is a guest | `np.maximum` over labels |
| Matrix labels | atoms outside every sphere are guests with probability `rho_b` | `gen_back_guest` |
| Observation | each atom is kept independently with probability η, whatever its label | `thin_cluster` |

Each `.npz` stores the centres and radii. θ = (`rho_c`, `rho_b`, `cr`, `rb`) is
in `experiments/inference/ground_truth/theta.npy`.

### 2.2 The target

For atom j, the target is

    p*_j = P(atom j is a guest | all atom positions, cluster geometry, θ)

Section 4.2 computes it by replaying the labelling. It is defined at atoms. For
rendering, a continuous field is given by each cluster's inclusion probability as
a function of distance from its centre (Stage 0).

The estimation task is this: given the observed atoms and their labels, predict
p* at the atoms thinning removed, and at any other location.

### 2.3 Five facts that decide the design

**F1. Thinning changes the sample size, not the target.** Whether an atom is kept
does not depend on its label, so kept atoms have the same p* as removed ones.
Nothing is missing that must be invented. The task is to estimate p* from ηN
labelled samples, and the question is how close an estimator gets to the oracle
at a given η.

**F2. Positions carry no information here; labels carry all of it.** Atoms are
uniform by construction. The likelihood is Bernoulli on the labels at the
observed positions, which is binary cross-entropy (BCE). A Poisson point-process
likelihood on positions models something this simulator never varies. Solute
conservation needs no loss of its own. With a free output bias, the gradient of
BCE with respect to that bias is Σ(p̂ − y), so at any stationary point Σp̂ = Σy
over the fitted atoms.

**F3. The target has edges.** Inside a sphere, p* falls monotonically towards
zero at the boundary, then jumps to `rho_b` (Section 3.2). A global smoothness
prior is misspecified exactly where reconstruction is hardest. Smoothness must
therefore be chosen by validation, never assumed.

**F4. Summary functions survive thinning.** Under independent thinning, K(r),
g(r) and related functions are unchanged in expectation. E6 measured this:
independent thinnings move the 14 features by only 4–9% of the between-pattern
spread, and discarding 95% of atoms barely changes them. The input's own K(r)
already estimates the truth's, so a reconstruction that reproduces K(r) has shown
nothing.

**F5. Held-out log loss measures distance to the truth without the truth.** For
one atom, the expected log loss of a prediction q is H(p*) + KL(p* ‖ q). The
entropy term H(p*) does not depend on the method. So on the removed atoms, the
difference in mean log loss between two methods equals the difference in their
mean KL divergence from the truth. The primary metric therefore needs no
ground-truth grid. The same protocol works on a real measurement: hold out a
random subset of the observed atoms, which independent thinning makes
statistically equivalent to removed atoms.

One caveat, recorded so it is not rediscovered. Within a cluster the number of
guests is fixed, so observed and held-out labels are weakly dependent. A
predictor that knew the geometry *and* the observed labels could beat p* by a
finite-population term of order 1/N_k. That term is negligible except for the
smallest clusters.

### 3.2 What is broken or misleading

**`fields.density_grid.generate_density_grid` is not a ground truth.** It was
checked against the simulator's realised labels on 60 development patterns
(12.96 million atoms), and against replays of a single cluster
(`pilot/check_density_grid.py`):

| Region | Share of atoms | Grid | Observed |
| --- | ---: | ---: | ---: |
| Matrix | 85.8% | 0.0256 | 0.0255 |
| Inside one sphere | 13.1% | 0.551 | 0.556 |
| Sphere rim, where within-cluster p < `rho_b` | 0.5% | 0.043 | 0.022 |
| Overlapping spheres | 0.6% | 0.475 | 0.550 |

The matrix is right. Inside clusters the grid is wrong in three ways.

- **The radial profile is too peaked.** The grid rescales the weights to mean
  `rho_c` and clips at 1. The simulator instead calls
  `rng.choice(replace=False, p=w)`, which is successive sampling, and its
  inclusion probabilities are flatter than the weights.
  - For one cluster of radius 8 at `rho_c` = 0.3, the grid puts the core
    (u < 0.3) at 0.927; the simulator gives 0.712.
  - At `rho_c` = 0.9, the grid puts the outer rim (u > 0.95) at 0.258; the
    simulator gives 0.457.
  - Pooled over patterns, among atoms where the grid averages 0.87, only 77% are
    guests.
- **Rims are floored at `rho_b`.** The simulator never makes a host atom inside a
  sphere into a background guest.
- **Overlaps take the maximum.** The simulator's labels combine as a union.

It also **raises an error** on 53, 55 and 60 of the 1,000 patterns at resolutions
0.5, 0.6 and 1.0. This happens whenever a cluster's bounding box contains no
voxel centre; 46 patterns contain a radius of exactly zero.
`LoadData(target_source="simulation")` inherits both problems.

**Cluster centres sit on a lattice.** In every pattern with enough distinct
centre coordinates to test (820 of 1,000), the centres lie on a cubic grid. The
grid is centred on the box and its spacing is fixed by the parameters. In 12 of
those patterns a whole plane of the grid was dropped by the subsampling. There is
no random offset and no jitter. A model trained across patterns can therefore
learn where clusters are *allowed* to be from global statistics alone. That is an
artefact of `clustersim`, which no real material shares. rapt's walkthrough,
which produced the published results, drew centres from a Poisson pattern
instead. It calls `clustersim(pattern, pattern, ...)` with one Poisson pattern as
both the overlying and the underlying pattern (`experiments/inference/generate_shared_upp.py`).
Stage 0 generates data with Poisson centres.

**Some lattice patterns received far fewer clusters than their parameters imply.**
Found in Stage 0, by regenerating every θ with random centres and comparing
cluster counts. The lattice is placed so that, for an odd number of points per
side, its outermost planes fall exactly on the edges of the window `clustersim`
keeps. Floating point then decides whether that whole outer shell survives.
Where it did not, the pattern received (side − 1)³ centres, and the random
subsample that normally trims the lattice to the intended count had nothing to
trim.

In 22 patterns of `data/`, the count is exactly (side − 1)³ and falls short of
the intended count by more than the volume estimate's rounding:

| Lattice side | Patterns | Clusters in `data/` | Intended |
| ---: | ---: | ---: | ---: |
| 3 | 18 | 8 | 11–25 |
| 5 | 2 | 64 | 72–81 |
| 7 | 2 | 216 | 326–328 |

Their realised solute fraction averages 0.062, against 0.098 for the other
patterns. By split, 2 are development patterns, 17 training, 1 validation and 2
test. The inference track trained on these patterns as generated, so the shortfall
is part of its forward model. The benchmark dataset does not have it, because it
draws eight times more random centres than it needs before subsampling.

**The July global barcode carries no information.**
`train_network_spatstat_02.py` appended `calculate_spatial_barcode` to the
coordinates, using `LoadData`'s default `barcode_marks="all"`. Atom positions are
uniform here, so a pair-distance histogram over all atoms cannot see clustering.
Over development patterns 0–99 (`pilot/check_global_barcode.py`):

- Its bins correlate with `cr` and `rho_c` at |Spearman| ≤ 0.10.
- Patterns differ from one another by 0.97–1.07 times the spread between two
  subsamples of the same pattern, which is pure resampling noise.
- The last bin is always exactly 1, because of the max normalisation.

Restricted to guest atoms, the same barcode correlates with `cr` at −0.50 and
with `rho_c` at +0.44.

**Earlier field experiments measured interpolation, not reconstruction.**

- The July run logged metrics only on its training patterns.
- The September `*_shared` stages split *voxels* of the same patterns into
  training and validation sets, against a target smoothed from 90% of all atoms.

Neither shows a model reconstructing an unseen pattern from the atoms an
instrument would record.

**No positional encoding exists** (`experiments/inference/ROADMAP.md` §12). Every existing
field is a ReLU MLP on raw coordinates.

### 3.3 Lessons carried over from E9

- Report every score beside a constant predictor and the oracle. A Brier score on
  its own cannot be interpreted.
- Measure headroom per pattern before comparing methods. E9 took its median over
  two solved problems and one unsolved one.
- Keep the atoms that define the target out of the model's inputs.
- Spatial-block validation cuts clusters apart. Scoring on held-out *atoms*
  avoids that.

## 4. Pilot measurements

These measurements size the problem. They use development patterns only, so
they cannot contaminate a gate.

### 4.1 Splits (fixed now)

| Split | Patterns | Use |
| --- | --- | --- |
| development | 0–99 | debugging, pilots, choosing thresholds; includes E9's patterns and every pattern inspected on 2026-09-14/15 |
| training | 100–799 | fitting models that learn across patterns (Stage 3) |
| validation | 800–899 | model selection for those models |
| test | 900–999 | scored once per stage, at its gate |

Per-pattern methods fit nothing across patterns, so they are gated on test
patterns directly. The two zero-cluster patterns (278 and 613) fall in the
training split.

### 4.2 An exact oracle by replay

`pilot/headroom.py` replays the labelling of Section 2.1 on the stored atoms,
centres and radii. It uses 12 development patterns stratified by `cr` and
`rho_c`, with 200 replays per cluster. Clusters combine as a union, and matrix
atoms get `rho_b` exactly. The realised labels are an independent draw from the
same process, so a correct oracle must be calibrated against them.

| Check | Result |
| --- | --- |
| Logistic recalibration on 390,300 in-sphere atoms | slope 0.981, intercept −0.004 (ideal: 1 and 0) |
| Largest gap across 10 reliability bins | 0.006 |
| Matrix guest fraction against `rho_b`, per pattern | for example 0.0468 vs 0.0461; 0.0033 vs 0.0031 |
| Cost | 1–2 s per pattern |

The 2% shortfall in slope is about what 200 replays of Monte Carlo noise in p*
should produce, and Stage 0 removes it. For comparison, the grid of Section 3.2
misses by up to 0.10 in a single bin.

### 4.3 How much room classical smoothing leaves

The same 12 patterns were thinned at η = 0.1, 0.37 and 0.8. Nadaraya–Watson
smoothing was fitted to the observed atoms. Its bandwidth was chosen on a
held-out fifth of the *observed* atoms only. The removed atoms were then scored.

"Gap closed" means (L_constant − L_smoothing) / (L_constant − L_oracle). A value
of 1 means smoothing matches the oracle; 0 means it does no better than a
constant.

| Cluster radius `cr` | Clusters per pattern | η = 0.1 | η = 0.37 | η = 0.8 |
| --- | ---: | ---: | ---: | ---: |
| 4.4–4.8 | 39–170 | 0.45–0.65 | 0.68–0.77 | 0.76–0.82 |
| 7.7–9.3 | 4–28 | 0.78–0.84 | 0.86–0.91 | 0.91–0.93 |
| 12.4–14.4 | 2–4 | 0.81–0.86 | 0.89–0.94 | 0.91–0.96 |

Each cell spans four patterns: two with `rho_c` below 0.5 and two above. The full
gap, constant to oracle, is 0.07–0.25 nats per atom.

Three findings shape the plan.

1. **The headroom is in small clusters.** With `cr` below 5, smoothing leaves
   18–55% of the gap open at every efficiency. With `cr` above 12 and η ≥ 0.37,
   it leaves only 4–11%. Part of that remainder is out of reach for any estimator,
   because the oracle knows the true geometry. Gates are therefore evaluated
   where headroom exists (Section 5.5).
2. **Bandwidth tuning is already solved.** The bandwidth chosen from observed
   atoms matched the best choice in hindsight in 28 of 36 cases, and was never
   more than 0.044 of the gap behind it. What smoothing leaves is structural.
3. **The error sits inside clusters.** For pattern 7 at η = 0.37, excess loss is
   0.29 nats per atom inside spheres against 0.03 in the matrix.

### 4.4 Compute on this machine

Measured by `pilot/timing.py` on an Apple M1 with 16 GB and torch 2.10. Times are
per optimiser step.

| Model | MPS | CPU |
| --- | ---: | ---: |
| Fourier-feature MLP, BCE, batch 32,768 | 51 ms | 140 ms |
| SIREN, BCE plus Laplacian residual on 8,192 points | 276 ms | 577 ms |
| 3D U-Net (0.42 M parameters) plus implicit decoder, 4 × 48³ crops, 16,384 queries | 1,101 ms | — |
| Oracle replay, per pattern | — | 1–2 s |
| Smoothing with bandwidth selection at 3 efficiencies, per pattern | — | 8–9 s |

What that means for each model:

- A per-pattern Fourier-feature fit of about 1,000 steps takes about a minute.
- A PINN fit of 3,000 steps takes about 14 minutes.
- A conditional-field training run of 10,000 steps takes about 3 hours.

Two environment facts:

- `F.grid_sample` has no 3D backward pass on MPS. Feature lookup therefore uses
  `gather`, as in the timing script's `trilinear`.
- This environment links two OpenMP runtimes, so `KMP_DUPLICATE_LIB_OK=True`
  must be set, as `experiments/neural_field` already does.

## 5. Evaluation protocol

This protocol is fixed before any model is fitted. Stages may add metrics but
may not remove these.

### 5.1 Observations

- **Efficiencies:** η ∈ {0.1, 0.37, 0.8}. The first is a stress test; the other
  two are the ends of the 37–80% range that E6 cites for real instruments.
- **Thinning:** one thinning per (pattern, η), from a seed stored in
  `experiments/reconstruction/benchmark/` with a checksum of the resulting mask. Every method
  sees identical observed atoms.
- **Selection uses observed atoms only.** This covers bandwidths, network
  frequency scales, regularisation weights and stopping epochs. Removed atoms are
  read once, for scoring.

### 5.2 Metrics

| Metric | Definition | Why |
| --- | --- | --- |
| **Excess log loss** (primary) | mean log loss on removed atoms, minus the oracle's | equals mean KL divergence from the truth (F5) |
| Gap closed | (L_const − L_method) / (L_const − L_oracle) | comparable across patterns |
| Excess by region | matrix beyond 2 units of any sphere; rim within 2 units of a sphere surface; core (u < 0.7) | 86% of atoms are matrix, so the overall mean hides the clusters |
| Brier excess | mean (p̂ − p*)² | a second, bounded view |
| Calibration | reliability curve and expected calibration error on removed atoms | a sharp field can still be miscalibrated |
| Cluster metrics (Stage 4) | detection F1 after matching centres; radius and composition error of matched clusters | what practitioners actually use |
| Predictive check | relabel every atom by Bernoulli(p̂); compare G, K and cross-G with the true pattern | necessary, but not sufficient (F4) |

### 5.3 What is never used

- The grid from `generate_density_grid` as a target.
- Metrics computed on patterns, or atoms, that a model was trained on.
- Voxel scores against kernel-smoothed "targets".
- Agreement in K(r) offered as evidence of accuracy.

### 5.4 Statistics

Comparisons are paired by (pattern, η). Report medians with bootstrap intervals
over patterns, together with win counts. Stratify by `cr` band (3–6, 6–10,
10–15), `rho_c` band (below or above 0.5) and η.

### 5.5 Headroom cells

A (pattern, η) cell *has headroom* when smoothing leaves at least 15% of the gap
open, and at least 0.01 nats per atom in absolute terms. In the pilot, 18 of 36
development cells qualify:

- all 12 with `cr` below 5;
- 4 of 12 at medium radius, all at η = 0.1;
- 2 of 12 at large radius.

Neural stages are gated on headroom cells, with a no-harm condition everywhere
else.

## 6. Staged roadmap

Each stage has a gate stated before it runs. A failed gate is recorded, not
adjusted, and the gate says what happens next.

### Stage 0 — The yardstick (2–3 days)

Build the oracle properly, and a benchmark without the lattice artefact.

**Oracle.** `geom_mesh_net/fields/oracle.py` provides:

- p* for every atom, by replay;
- each cluster's inclusion probability as a function of distance, for rendering
  a continuous field at any point;
- the union rule for overlaps and exact `rho_b` in the matrix.

**Monte Carlo noise.** Remove the slope shortfall of Section 4.2. Either fit each
cluster's replay frequencies as a monotone function of weight (inclusion
probability under successive sampling increases with weight), or raise the
replay count for small clusters. Verify against brute-force replays.

**Speed.** Successive sampling is equivalent to picking the n atoms with the
smallest E_i / w_i, where each E_i is an independent exponential draw. Verify
that equivalence against `rng.choice` before relying on it.

**Benchmark dataset.** Regenerate the 1,000 θ with a Poisson overlying pattern,
as the published design did, using `experiments/inference/generate_shared_upp.py` as the
template. Write the result to `data_random_centres/` (about 5 GB, gitignored).
This becomes the benchmark for every stage; `data/` is kept for Stage 3's lattice
comparison. Store checksums of the generated files. `estimate_cluster_volume`
draws from NumPy's unseeded global generator, so regeneration is not
bit-identical.

**Tests** (`tests/test_field_oracle.py`):

- calibration on synthetic patterns built inside the test fixtures;
- limits with closed forms: all atoms selected gives 1, none gives 0, no clusters
  gives `rho_b`, and zero-radius clusters are ignored;
- the union rule, checked against brute-force simulation of two overlapping
  clusters.

**`generate_density_grid`.** Either fix it (the error, the union rule, the floor
and the profile) or deprecate it in favour of the oracle. Add a regression test
either way.

**Freeze the benchmark:** splits, strata, efficiencies, seeds and mask checksums.

**Gate 0.** All of the following, on the in-sphere atoms of development patterns
0–99:

- logistic recalibration slope in [0.99, 1.01] and |intercept| ≤ 0.01;
- every reliability bin holding at least 10,000 atoms lies within
  max(0.005, three standard errors) of the observed fraction;
- the matrix guest fraction lies within three standard errors of `rho_b` in at
  least 95 of the 100 patterns;
- the tests pass, and the masks regenerate identically.

**If it fails, stop.** Nothing downstream can be scored.

**Result: PASSED** (2026-09-15). Measured on 2,879,952 in-sphere atoms of the
benchmark's development patterns by `experiments/reconstruction/stage0_oracle.py`, with
1,000 replays per cluster. The full report is
`experiments/reconstruction/results/stage0_gate.json`.

| Condition | Required | Measured | |
| --- | --- | --- | --- |
| Recalibration slope | [0.99, 1.01] | 1.0007 ± 0.0013 | pass |
| Recalibration intercept | \|·\| ≤ 0.01 | −0.0000 ± 0.0015 | pass |
| Reliability bins | each within max(0.005, 3 s.e.) | largest gap 0.0008, over 10 bins | pass |
| Matrix guest fraction | within 3 s.e. in ≥ 95 of 100 | 99 of 100 | pass |
| Tests | pass | 178 passed | pass |
| Masks | regenerate to frozen checksums | 900 of 900 | pass |

For comparison, the pilot oracle (200 replays, no smoothing) had a slope of
0.981, and `generate_density_grid` misses by up to 0.10 in a single bin. The same
checks on the lattice dataset `data/`, reported without a gate, give a slope of
0.9984 ± 0.0012 and a largest bin gap of 0.0015. The oracle is correct for both
datasets.

Findings and decisions:

- **NumPy's weighted sampling without replacement is successive sampling.**
  `rng.choice` and exponential clocks both reproduce exact enumeration for a
  six-atom population. On a realistic 113-atom cluster at 200,000 replays, the
  two methods differ no more than two runs of the same method, and the difference
  does not grow with replays, as a bias would.
- **The oracle matches the simulator atom by atom.** On a full `clustersim`
  pattern, 6,000 replays of the simulator's own labelling functions against a
  200,000-replay oracle give mean z² = 1.040, with sd 0.042 under pure noise.
- **Isotonic smoothing removes the Monte Carlo attenuation.** It raised the slope
  from the pilot's 0.981 to 1.0007 at five times the replays. In a 4,000-atom
  cluster it cuts squared error by more than a factor of 5 at equal replays.
- **The benchmark dataset** (`data_random_centres/`, 5.0 GB, gitignored):
  - generated in 95 s with no failures, and no pattern has lattice centres;
  - 956 of 1,000 cluster counts are within one of `data/`, and the exceptions are
    the lost shells of §3.2 plus rounding at large counts;
  - NumPy's global generator is seeded per pattern, so regeneration is
    deterministic. Regenerating the first three patterns reproduced their
    checksums in `experiments/reconstruction/benchmark/dataset_checksums.json` bit for bit.
    That corrects the plan above, which expected otherwise.
- **`clustersim` gained `opp_oversample`**, defaulting to 1. A test confirms the
  default reproduces every label, radius and centre unchanged.
- **`generate_density_grid` is deprecated, not repaired.** It now warns that it is
  not the simulator's field and points to the oracle, and it no longer raises on
  zero or tiny radii. Its profile, rim floor and overlap rule are left as they
  were, because `LoadData` and earlier results depend on them.
- **The Stage 2 subset is full:** six test patterns in every (`cr` band × `rho_c`
  band) cell.

A correction, recorded. The first version of the atom-by-atom test compared
simulator replays with a 4,000-replay oracle, using only the replays' own
binomial variance. It failed at z² = 1.39 and was briefly read as a possible bias.
The oracle's own Monte Carlo variance predicts 1.375, and counting it gives 1.009.
The test now counts both variances. The investigation it prompted is the
evidence behind the first two findings above.

### Stage 1 — Baselines and the headroom map (3–4 days)

**Baselines** (`geom_mesh_net/fields/baselines.py`):

- **B0**, a constant: the observed guest fraction.
- **B1**, Nadaraya–Watson smoothing with a Gaussian bandwidth chosen by five-fold
  cross-validation on observed atoms. This is the delocalisation estimator of
  standard practice.
- **B2**, adaptive bandwidth: each kernel's width is set by the distance to the
  k-th nearest observed atom, with k chosen by cross-validation.

**Run** all 100 test patterns at the three efficiencies (estimate: under an hour
on six workers).

**Deliver** the headroom map: excess loss and gap closed, by stratum and by
region.

**Gate 1.** At least 25% of test cells have headroom (Section 5.5). The pilot
suggests roughly 40% under the prior; this is an estimate from 12 patterns.
**If it fails:** classical smoothing is within 15% of the oracle almost
everywhere. Record that as the result, skip Stages 2 and 3, and take B1 to
Stage 4.

**A correction to B2, recorded before any test pattern was scored**
(2026-09-15). As written above, B2 sets each kernel's width from the distance to
the k-th nearest *observed atom*. Atom positions are uniform in this simulator
(F2), so that distance is almost the same everywhere, and B2 would reduce to B1
plus noise. The adaptive estimator therefore adapts to the density of observed
*guest* atoms instead, which is high inside clusters and low in the matrix:

- the width at query point x is h(x) = c · d_k(x), clipped to [0.75, 6], where
  d_k(x) is the distance to the k-th nearest observed guest atom;
- k ∈ {4, 8, 16, 32, 64} and c ∈ {0.25, 0.35, 0.5, 0.7, 1} are chosen together
  by the same five-fold cross-validation as B1. The c grid was first {0.5, 1}.
  A smoke test on development patterns 0 and 1 found cross-validation choosing
  c = 0.5, the grid's edge, in all six cells, with c = 1 worse by 0.01–0.04 nats.
  The grid was widened before any test pattern was scored, so that B2 is not an
  under-tuned baseline;
- h(x) is realised by interpolating, in log bandwidth, between Gaussian-smoothed
  fields precomputed at B1's bandwidth grid {0.75, 1, 1.5, 2, 3, 4.5, 6}. B1
  chooses from that same grid.

**Operational definitions fixed before the Stage 1 test run** (2026-09-15). These
close open definitions O1 and O2 and add O11.

- **Regions (O1).** Each scored atom gets one region, tested in this order,
  ignoring clusters of zero radius:
  1. *rim*, if some cluster has |d − r| ≤ 2;
  2. *core*, if some cluster has d/r < 0.7;
  3. *matrix*, if it lies outside every sphere;
  4. *interior* otherwise.
- **Expected calibration error (O2).** Twenty equal-width bins on the predicted
  probability q. ECE = Σ over bins of (share of scored atoms) × |mean label −
  mean q|.
- **Predictive check (O11).** For each cell and method, every one of the 216,000
  atoms is relabelled once as a guest with probability q, from a stored seed.
  - The 14 global features are computed with the inference track's `stage1`
    configuration, both for the relabelled pattern and for the realised pattern.
  - The difference is standardised by the between-pattern standard deviation of
    each feature over the 100 test patterns' realised values.
  - Results are summarised as the median |z| per feature family: G, F, K and
    cross-G.
  - Relabelling from the oracle gives the sampling floor.
  - The check is reported, not gated (F4).

### Stage 2 — A field fitted to one pattern (1 week)

*Question: fitted only to one pattern's observed atoms, does a coordinate network
with positional encoding estimate p\* better than B1 and B2?*

**Model** (`neural/implicit.py`): Gaussian random Fourier features (Tancik et al.,

scale, width and stopping point are chosen on a held-out fifth of the observed
atoms.

**Control:** the existing ReLU MLP on raw coordinates. Comparing Fourier features
against it removes the spectral-bias confound named in `experiments/inference/ROADMAP.md`
§12.

**Ablation, with a stated prediction:** a gradient penalty λ·mean‖∇f‖², computed
by autograd. The prediction is that validation selects λ ≈ 0, and that forcing
λ > 0 raises rim excess loss (F3).

**Scope:** 36 test patterns (6 per `cr` band × `rho_c` band cell), 3
efficiencies, and about 4 candidate frequency scales. Estimate: 8 hours on MPS.

- beat the better of B1 and B2 on held-out log loss in at least two-thirds of
  cells;
- close at least 20% of B1's remaining gap in the median cell;
- have an expected calibration error no more than 0.005 worse than B1's.

atom worse than B1's.

**If it fails,** record that at this sample size a per-pattern field is a
reparameterised smoother, and continue. Stage 3 learns across patterns, which is

Rerunning E9's local-feature comparison with this baseline is out of scope unless
Gate 2 passes.

### Stage 3 — A field trained across simulations: a learned prior (1.5–2 weeks)

*Question: trained on simulated patterns, can a network reconstruct unseen
patterns better than any per-pattern estimator, by learning what precipitates
look like?*

**Architecture.** This follows the convolutional occupancy network and IF-Net
family (Peng et al., 2020; Chibane et al., 2020).

- Observed atoms are binned into a 1-unit grid with two channels: atom count and
  guest count. η is implicit in the count channel.
- A 3D U-Net turns that grid into a feature grid.
- An MLP decoder reads trilinearly interpolated features plus Fourier features of
  the query's position within its voxel, and outputs p̂(x).

**Training** uses patterns 100–799 of `data_random_centres/`. Each step draws:

- a pattern;
- an efficiency η ~ U(0.08, 0.9);
- a 48³ crop;
- one of the cube's 48 symmetries, which is valid because the process is
  isotropic within the cube.

The loss is BCE on the labels of the *removed* atoms in the crop. Its minimiser
is P(guest | observation), the posterior predictive field. That is the same
property that makes neural posterior estimation work in the inference track.

**Model selection** uses patterns 800–899.

**Ablations:**

- (a) no implicit decoder, predicting voxel values directly;
- (b) no positional features in the decoder;
- (c) global summary statistics of the guest atoms, injected by FiLM. This is
  Path 1 done correctly (Section 7), and it is predicted to add little once the
  encoder sees the atoms;
- (d) the oracle p* as a soft target instead of labels.

**Lattice comparison.** Train and test the same model on the lattice-placed
patterns of `data/`. The improvement over the random-centre result measures how
much a learned prior exploits where `clustersim` puts its centres.

**Out-of-distribution test, with a stated prediction.** 50 patterns are simulated
outside the training distribution:

- ellipsoidal clusters, using `clustersim`'s axis weights;
- `cr` in [15, 20];
- flat selection within clusters (`prob_function="constant"`).

The prediction is that the learned prior degrades more than B1 does, most on
ellipsoids. This measures when a learned prior invents structure.

**Estimated compute:** about a day of machine time, covering the main model,
ablations and seeds.

**Gate 3.** On test headroom cells, the conditional field must:

- beat the best of B1, B2 and Stage 2 in at least two-thirds of cells;
- close at least 30% of B1's remaining gap in the median cell;
- have an expected calibration error of at most 0.01;
- have no stratum where its median is worse than B1's.

The out-of-distribution result gates the *claim* of robustness, not progress to
the next stage. **If the gate fails,** record it: the simulator has not taught
the network more than smoothing already knows. Stage 4 then proceeds with the
best field available.

### Stage 4 — From fields to precipitates, against standard practice (1 week)

*Question: do reconstructed fields find precipitates, and measure their sizes and

**Code** (`fields/cluster_extraction.py`):

- isosurface segmentation of any field, with the threshold chosen on validation
  patterns;
- the maximum separation method and DBSCAN on observed guest atoms, with their

**Compared:** isosurfaces of B1 (delocalisation, the standard route), the maximum
separation method, DBSCAN, and isosurfaces of the Stage 2 and Stage 3 fields.

**Metrics against the stored geometry:**

- radius error and composition error of matched clusters, with composition

- matrix composition error;
- counts of split and merged clusters.

**Shared with the inference track.** Compute population estimates (mean radius,
radius spread, `rho_c`, `rho_b`) from each segmentation and compare them with the

**Path 3 ablation.** Penalise mismatch between a field's implied K(r) and the

**Gate 4.** At η = 0.37, on test patterns with at least two true clusters, the
best field-based segmentation must beat the better of the maximum separation
method and DBSCAN:

- on F1 in at least two-thirds of patterns;
- and on median matched-radius error.

**If it fails,** record the regimes where cluster finding wins.

### Stage 5 — A physics-informed field with a governing equation (1.5–2 weeks)

This is where "physics-informed" is earned. Section 8 explains why nothing before
this stage qualifies.

#### 5.1 Give the simulator physics a PINN can use

`clustersim`'s matrix is uniform, so no differential equation constrains it. The
fix is to add a quasi-stationary diffusion field around precipitates, in
`fields/physics.py`. Outside every sphere, the matrix guest probability becomes

    c(x) = c∞ + Σ_k (c_k − c∞) · (R_k / |x − x_k|) · exp(−(|x − x_k| − R_k) / ξ)

The quantities in it:

- **Interface concentration** c_k comes from the Gibbs–Thomson relation,
  c_k = c_eq · exp(ℓ / R_k), where ℓ is the capillary length.
- **Screening length** ξ = (4π n R̄)^(−1/2) ≈ R̄ / √(3φ). This is the mean-field
  sink-strength result for precipitate number density n and volume fraction φ,
  computed from each pattern's geometry.
- **Far-field concentration** c∞ is set so the mean matrix concentration equals
  the sampled `rho_b`.

Physically, large precipitates (c_k < c∞) sit in depletion zones, and small ones
(c_k > c∞) are surrounded by enrichment.

Each term solves (∇² − ξ⁻²)(c − c∞) = 0 away from its own centre, and so does
their sum. The field therefore satisfies the PDE exactly throughout the matrix,
and its oracle is analytic. The priors for c_eq and ℓ are set so that ℓ/R spans
roughly 0.05–1 over the radius prior. Generate 50 development and 100 test
patterns on random centres; each takes seconds.

**Gate 5.1.**

- The PDE residual of the analytic field, evaluated by autograd at random matrix
  points, is below 10⁻⁸ relative to the field's variation.
- Fewer than 0.1% of matrix atoms need c(x) clipped into [0, 1].
- The oracle passes the calibration checks of Gate 0.

#### 5.2 The physics-informed network

A per-pattern field with smooth activations: SIREN or tanh. A ReLU network's
Laplacian is zero almost everywhere, so it cannot be used. The loss has three
terms:

    L = BCE(labels of matrix atoms)
      + λ_pde · mean[ (∇²c − ξ⁻²(c − c∞))² ]        at collocation points in the matrix
      + λ_bc  · mean[ (c − c_eq · exp(ℓ / R_k))² ]   at segmented interfaces

c_eq, ℓ, ξ and c∞ are trainable scalars. The network therefore fits the field and
recovers the physical constants that generated it, which is the standard PINN
inverse problem. The physics adds information because two global constants tie
together the depletion amplitudes of every precipitate. Those amplitudes, around
0.01, are too faint for smoothing to resolve one precipitate at a time.

The matrix mask, the interfaces and the radii R_k come from a thresholded B1
field. The method therefore uses nothing a real measurement lacks. A joint
free-boundary version, with a learned phase indicator, is an extension if 5.2
passes.

Controls, each with a stated prediction:

| Control | Prediction |
| --- | --- |
| Same network with λ_pde = λ_bc = 0 | worse matrix excess loss, most of all at low η |
| B1 smoothing | worse still in the matrix |
| Parametric oracle: the analytic family fitted with the true centres and radii | an upper bound that the PINN approaches |
| **Misspecified data:** matrix fields that violate the PDE, namely 1/r² profiles and Gaussian-smoothed random fluctuations | the acceptance rule below rejects the physics |

**Acceptance rule.** Physical constants are reported for a pattern only if the
PINN's loss on held-out *observed* atoms is no worse than the unconstrained
network's. A physics prior is safe only if the method can tell, from data it
actually has, when the physics does not apply.

**Scope:** 24 test patterns at η = 0.37 and 12 at η = 0.1, with the collocation
set reduced until a fit takes under 10 minutes (Section 4.4).

**Gate 5.2.** The thresholds are fixed on the 50 development patterns and written
into this document before the test run. The PINN must meet all three conditions:

- **(i)** beat the λ = 0 network on matrix excess loss in at least two-thirds of
  correctly specified test patterns;
- **(ii)** recover ℓ and ξ with median relative error below the committed
  threshold;
- **(iii)** have the acceptance rule accept the physics in at least two-thirds of
  correctly specified test patterns *and* reject it in at least two-thirds of
  misspecified ones.

**If (iii) fails,** the method cannot detect its own misspecification, and no
physics-informed claim is made, whatever (i) and (ii) show.

**A correction to Stage 5, recorded 2026-09-16, before any Stage 5 network was
fitted or test pattern generated.** Three measurements on development data changed
the design of 5.1. Each gate's purpose is unchanged; where a condition changed, the
reason is given.

*1. The field as first written does not satisfy its own boundary condition.* Adding
single-precipitate profiles, (c_k − c∞)(R_k/r)·exp(−(r − R_k)/ξ), leaves every surface
carrying its neighbours' tails, so the surface value is not c_k. This was measured on the
benchmark geometry of development patterns 0–49 (`pilot/check_diffusion_field.py`), with
c_eq at half the matrix concentration:

- the mean over each precipitate's exposed surface missed c_k by a median 1.25–1.30
  times the depletion amplitude, and single points at isolated precipitates missed it by
  0.62–0.65 times;
- more than 0.1% of matrix atoms fell outside [0, 1] in 22–45 of 47 patterns, which
  fails Gate 5.1.

The field now solves for the amplitudes so that every precipitate's mean surface value
equals c_k exactly (`geom_mesh_net/fields/physics.py`). The mean-value property of the
equation turns those K conditions into a K × K linear system. The equation still holds
exactly throughout the matrix. Single surface points depart from their mean by the
multipoles the solution leaves out. On the same geometry the solve cut the
exposed-surface error to 0.06–0.10, and the error at single points of isolated
precipitates to 0.07–0.08, times the amplitude.

The boundary term of 5.2 changes to match. It penalises each precipitate's surface
mean, λ_bc · mean_k[(mean of c over surface k − c_eq·exp(ℓ/R_k))²], with the mean
estimated from points on each segmented interface.

*2. The benchmark geometry cannot carry a boundary condition.* In the same patterns a
median 77% of spheres overlap another, and 39 of 47 patterns have a centre inside
another sphere. There the mean-value step fails: even the solved field put more than
0.1% of matrix atoms outside [0, 1] in 18–22 of those 39 patterns, and in none of the
other 8.

Stage 5 therefore generates its own patterns, 50 development and 100 test, in
`data_diffusion/` (`generate_diffusion_patterns.py`). clustersim gained two options, both
off by default:

- `min_gap` places precipitates so that no two come closer than the gap, surface to
  surface, rejecting positions rather than radii;
- `r_min` redraws radii below a floor, which also keeps exp(ℓ/R) finite.

With both off, clustersim reproduces benchmark pattern 0 exactly
(`tests/test_clustersim.py`). Stage 5 uses a gap of 1 and a floor of 2. Precipitates
keep clustersim's in-sphere labelling, so the replay oracle still holds inside them.

*3. Under the first prior, no method could recover the capillary length.* The
Cramér–Rao bound is the smallest relative error that any unbiased fit to the observed
matrix labels can reach when it knows the true precipitate geometry. The network, which
must segment the geometry, can only do worse.

- On the benchmark geometry at η = 0.37, the bound on ℓ was below 25% in at most 13 of
  47 patterns at the patterns' own matrix concentrations.
- A first Stage 5 prior, with about 100 small precipitates per pattern, still gave a
  median bound of 45% on ℓ (`pilot/compare_diffusion_priors.py`, prior A).

The information about ℓ comes from how the surface values change with radius. It
scales with c_eq and needs a spread of radii. The screening length is read from the
depletion and enrichment zones, which partly cancel where growing and dissolving
precipitates mix.

Nine priors were compared on 12 patterns each. Two, F and I, identified both constants
best, but by making every precipitate dissolve. That contradicts the physical picture of
5.1, in which large precipitates grow in depletion zones while small ones dissolve. The
prior chosen keeps that picture. Its median bounds at η = 0.37 were 15% on ℓ and 32% on
ξ over the 12 comparison patterns, and 13% and 20% over the 50 development patterns.

**Open definition O8, fixed.** All parameters are uniform:

- cr ∈ [3, 4] and rb ∈ [0.2, 0.4];
- precipitate volume fraction ∈ [0.08, 0.12], with pcp following from it;
- rho_c ∈ [0.4, 0.9];
- matrix concentration ∈ [0.05, 0.15];
- ℓ ∈ [2, 5];
- critical radius R* ∈ [0.6, 0.8] × cr, which sets the supersaturation

Measured on the 50 development patterns (`pilot/check_diffusion_prior.py`):

### Stage 6 — Measurement physics in the loss: position blur (1 week, optional)

*Question: when positions are blurred the way a real instrument blurs them, does
putting the known blur inside the loss recover the sharp field?*

**Forward model.** The observed position is x̃ = x + ε, with
ε ~ N(0, diag(σ_xy², σ_xy², σ_z²)), wider laterally than in depth. Because atoms
are uniform, P(guest | x̃) = (p* ∗ N_Σ)(x̃): labels at blurred positions follow the
blurred field.

**Method.** Model the sharp field f and train on BCE(y, E_ε[f(x̃ − ε)]),
estimating the expectation with a few draws of ε per atom. Score f against the
sharp oracle at the true positions.

**Compared against:**

- a naive fit that ignores blur, which learns the blurred field;
- B1 on the blurred data;
- the Stage 3 network retrained with blur augmentation.

**Prediction.** Per-pattern deblurring helps only while σ is well below the
cluster radius, and amplifies noise beyond that. The network trained across
simulations does best, because deconvolution needs a prior.

**Capstone,** if Stages 5 and 6 both pass: a diffusion-field microstructure
observed through blur and thinning, with both kinds of physics in one loss.

**Gate 6.** The thresholds are fixed on development patterns before the test
run. The forward-model fit must beat the naive fit on excess loss against the
sharp oracle in at least two-thirds of test patterns, at the two smallest blur
levels.

## 7. Spatial statistics in the network: the three proposed paths

Three ways to use spatial statistics were proposed on 2026-09-15. One claim runs
through all three, and it is wrong: that adding spatial statistics turns a
network into a physics-informed neural network. Spatial statistics summarise a
point process. They are not laws. Using them as inputs or as loss targets does
not enforce a governing equation (Section 8).

### Path 1: global statistics as extra inputs

**Proposal:** append g(r) or K(r) at five radii, computed from the thinned atoms,
to (x, y, z).

**This was built in July,** as `statistics.barcode.calculate_spatial_barcode`,
`LoadData`'s `spatial_features`, and `ContinuousNeuralFieldspatstat_01` with
`nn.Linear(3 + 5, 128)`. Section 3.2 measured what it fed the network: nothing,
because it counted all atoms, and atom positions are uniform.

Computed on guest atoms, the statistic does carry information. The design still
cannot work as described:

- **For one pattern,** a global statistic is the same five numbers at every
  coordinate. It is a constant input, and a network learns nothing from a
  constant except a bias.
- **Across patterns,** it says *what kind* of clustering a pattern has, never
  *where* the clusters are. Knowing that a box holds dense clusters does not say
  whether (30, 30, 30) is inside one. A network that sees only (x, y, z,
  statistics) can localise clusters only through the lattice artefact of
  Section 3.2: the statistics identify the lattice spacing, and the spacing fixes
  where centres may sit. That would be learning `clustersim`, not materials, and
  it would fail on any real sample.

It only makes sense as *regime conditioning* for a network that already sees the
local observed atoms. That is Stage 3's ablation (c), and it is predicted to add
little, because the encoder can compute such statistics for itself.

### Path 2: a CNN plus hand-computed statistics, predicting `rho_c` and `rho_b`

This is parameter inference, not reconstruction, and it belongs in
`experiments/inference/ROADMAP.md`.

The architecture is sound: a learned summary of the voxelised observations,
concatenated with hand-built statistics. The target is not.

- `rho_c` and `rho_b` are already recovered with calibrated posteriors. Their 90%
  intervals cover the truth 91.9% and 90.2% of the time, with R² of 0.96 and
  0.93.
- A point-estimate regression would throw that calibration away.

The version worth running feeds the learned summary and the 14 features into the
*existing* flow. It should target what the features cannot see:

- `rb`, where R² is 0.11 and posterior contraction 0.04;
- the sharpness of `cr`, where contraction is 0.65.

A CNN can count clusters and measure individual radii, which is exactly the
radius-spread information a pair-distance statistic averages away. Judge it by
calibration and posterior contraction, not by mean squared error. Train it on
random-centre data, for the reason given under Path 1. Stage 3's encoder can
serve as the CNN.

### Path 3: a K(r)-matching term in the loss

**Proposal:** total loss = BCE + α·MSE(K of the predicted field, K of the ground
truth).

Two parts of this are right.

- **A reference K(r) is available without ground truth.** By F4, the observed
  atoms' K(r) is an unbiased estimate of the truth's.
- **K(r) of a field is differentiable.** With labels independent given p, the
  expected guest pair count is λ² ∬ p(x) p(y) 1(|x − y| < r) dx dy. The
  translation-corrected K then follows from the autocorrelation of p over the box,
  divided by the box's own set covariance. Both can be computed by FFT.

The rest is not.

- **It is not physics.** It is moment matching.
- **It does not pin down the geometry.** Many different fields share one K(r).
- **It works against the likelihood.**
  - The field that minimises expected BCE is the posterior mean,
    E[p* | observation].
  - Where the network is unsure where an edge lies, that mean blurs the edge.
  - A blurred field has less short-range correlation than the true field is
    expected to have, because the posterior covariance between nearby points is
    positive.
  - So the BCE-optimal field *should* have a lower K(r) at short range than the
    truth.

  Forcing it to match buys realism at the price of accuracy: the
  perception–distortion trade-off (Blau & Michaeli, 2018). Held-out log loss gets
  worse by construction.

It does have proper places:

- as the predictive check of Section 5.2;
- as the Stage 4 ablation, where sharper edges might improve radius estimates
  even while log loss worsens;
- in the tradition it actually belongs to, reconstructing random media from
  correlation functions (Yeong & Torquato, 1998). That tradition is the right
  tool when the goal is a *plausible sample*, not the best estimate.

## 8. What "physics-informed" means here

A physics-informed neural network, in the sense of Raissi, Perdikaris and
Karniadakis (2019), adds a physics residual to the data misfit. The residual is
that of a governing differential equation, evaluated by automatic differentiation
at collocation points. Such a network can also recover unknown coefficients of
the equation.

The wider physics-informed machine learning literature (Karniadakis et al., 2021)
distinguishes three routes by which physics can enter a model:

- **observational bias:** the training data are generated by physics;
- **inductive bias:** the architecture respects the physics, for example its
  symmetries;
- **learning bias:** the loss penalises violations of the physics.

Each component proposed for this track, classified:

| Component | Route | Legitimate here? | Stage |
| --- | --- | --- | --- |
| Training on simulator output | observational | yes, provided the simulator's artefacts, such as the lattice, are removed first | 3 |
| Cube symmetries during training | inductive | yes: the process is invariant under them | 3 |
| BCE with implied solute conservation | — | it is simply the correct likelihood; conservation comes free (F2) | 2 |
| Gradient or Laplacian smoothness penalty | learning | **no**: `clustersim` has no diffusion, and its edges come from a sampling rule (F3) | 2, as an ablation only |
| Spatial statistics as inputs (Paths 1 and 2) | none | conditioning, not physics | 3; inference track |
| Matching K(r) (Path 3) | none | moment matching | 4 ablation; predictive check |
| Blur operator inside the loss | learning, from measurement physics | yes, once positions are blurred | 6 |
| Screened diffusion equation and Gibbs–Thomson condition, with ℓ and ξ inferred | learning; a PINN proper | yes, once the simulator contains that physics | 5 |

Only the last row makes this a PINN, and it requires changing the simulator. A
PDE residual counts as physics only when the data obey the PDE. Imposed on
`clustersim`'s uniform matrix, a diffusion equation is satisfied trivially by a
flat field and adds nothing. Imposed on its cluster edges, it contradicts how
those edges were made.

## 11. Risks and limitations

**Headroom depends on the regime.** Section 4.3 showed that large clusters at
η ≥ 0.37 leave little room. The oracle's knowledge of the true geometry puts part
of that remainder out of reach for any estimator. Null results are expected
there, which is why gates are evaluated on headroom cells.

**The oracle conditions on geometry,** not on the observed labels. The
finite-population term of F5 is small, but it is not zero for the smallest
clusters. Removing the oracle's Monte Carlo noise is Stage 0's job.

**Learned priors can invent structure.** Stage 3's lattice comparison and its
out-of-distribution test exist to measure how much.

**The lattice affects the inference track too.** Its flow was trained on
lattice-placed clusters, and whether its features encode that regularity has not
been measured. `data_shared_upp/` keeps the lattice as well, because
`generate_shared_upp.py` still builds centres from `gen_uniform_points`. rapt used
Poisson centres, so this is a design difference missing from the comparison table
in `README_detailed.md` §5.3. The same lattice gave 22 patterns of `data/` far
fewer clusters than θ implies (§3.2). That is not yet recorded in
`experiments/inference/ROADMAP.md`.

**The simulator defines what is being reconstructed.**

- Uniform atom density rules out local magnification effects.
- Precipitates are spheres.
- There are no trajectory aberrations and no mass-spectral overlaps.
- Stage 5's diffusion field is a modelling choice (quasi-stationary, screened and
  superposed), not a phase-field simulation.

Every result is simulation-to-simulation, and `README_detailed.md` §5.4 applies
unchanged.

**The average hides the clusters.** 86% of atoms are in the matrix, so
region-by-region reporting is essential.

**Compute.** Stage 5 fits take minutes each and Stage 3 training runs take hours
(§4.4). On MPS, 3D `grid_sample` has no backward pass.

**Scope.** Stage 6, and the free-boundary extension of Stage 5, are optional.
Stop at gates.

## 13. Describing the results accurately

Each claim below becomes available only once its gate passes.

| After | Claim |
| --- | --- |
| Stages 0–1 (no gate needed) | "Built an exact oracle for the solute field of simulated atom probe data, and measured how close standard delocalisation gets to it: within X% for large precipitates and Y% for small ones." |
| Gate 2 | "A Fourier-feature implicit field, fitted to a single thinned point cloud, recovers small precipitates better than tuned delocalisation." |
| Gate 3 | "A conditional implicit field trained on simulations reconstructs unseen patterns closer to the truth than any per-pattern method, judged on held-out atoms with a proper scoring rule. Out-of-distribution tests show where its learned prior misleads." |
| Gate 4 | "Reconstructed fields identify precipitates, and measure their radii, better than the maximum separation method." |
| Gate 5.2 | "A physics-informed network that enforces a screened diffusion equation and the Gibbs–Thomson condition recovers solute depletion profiles and the capillary length from sparse, noisy labels, and rejects its physics when the data violate it." |

**Accurate connections:**

- Stage 3's architecture belongs to the family used to reconstruct 3D shapes and
  human bodies from sparse point clouds (occupancy networks, IF-Nets).
- Stage 5 is a PINN inverse problem with parameter discovery.
- The inference track is simulation-based inference.

**Claims to avoid:**

- that a network "hallucinates" missing atoms;
- that it "respects thermodynamics", unless Gate 5.2 passes;
- that it is "identical to NeRF";
- that matching K(r) validates a reconstruction.
